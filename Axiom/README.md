# Axiom v0.1-alpha.2 — Foundation Hardening

Локальная AI-платформа: первая рабочая версия **Axiom Chat** и независимый **Axiom Core** для будущих Chat, Code и CLI. Эта итерация укрепляет существующий фундамент без перехода к v0.2. Версия npm-пакетов: `0.1.0-alpha.2`.

## Запуск

Требуется **Node.js 24.15+** (проверено на 24.19.0) и npm. Все команды выполняются из корня проекта.

```powershell
cd C:\Axiom
npm install
npm run dev
```

Открыть **http://127.0.0.1:5173**. API работает на `127.0.0.1:3001`; Vite перенаправляет `/api` к нему. Порты должны быть свободны. Axiom Mock доступен сразу, без ключей, локальных LLM и настройки окружения. Остановить серверы: `Ctrl+C`.

Production, на одном порту:

```powershell
npm run build
npm start
```

Открыть **http://127.0.0.1:3001**. Если dev-сервер уже запущен, сначала остановить его. `npm start` запускает собранный сервер и раздаёт собранный Chat. Сервер импортирует внутренние пакеты из их `dist`, а не включает их исходники в bundle. Исполнение проверено в Node с отключённой поддержкой TypeScript. При переносе приложения сохраняйте workspace-пакеты, их `dist` и установленные зависимости.

## Что доступно

- Тёмный адаптивный интерфейс, история, создание, удаление, переименование и локальные автоматические названия.
- Потоковые ответы, остановка с сохранением частичного текста, редактирование сообщения с заменой последующей истории, повтор последнего ответа.
- Markdown, таблицы, подсветка кода, копирование кода и сообщений.
- Поиск моделей, группы провайдеров, избранное, контекст и объявленные capabilities. Неизвестные возможности не выдаются за поддерживаемые.
- Mock Provider и настраиваемый OpenAI-compatible Chat Completions: Base URL, ключ, ручной список моделей, обнаружение `/models`, проверка подключения.
- Текстовые вложения до 100 КБ, PNG/JPEG/WebP до 2 МБ при включённой поддержке изображений у модели, до 4 вложений через UI. Содержимое сохраняется с сообщениями.
- SQLite, серверное хранение ключей, понятные ошибки и восстановление после прерывания процесса.

## Настроить модель

1. Открыть **Настройки** → **Своё подключение** или готовый пресет.
2. Указать имя, Base URL (например, `http://localhost:1234/v1`) и при необходимости API Key.
3. Оставить список моделей пустым для обнаружения или ввести точные ID по одному на строку.
4. Нажать **Сохранить и проверить**. Проверка обращается к `/models`, без платного запроса генерации. Успешный `/models` не гарантирует доступ к каждой модели для генерации.
5. Вернуться в чат и выбрать модель. Если сервер не поддерживает `/models`, сохранённые ручные модели остаются доступны.

OpenAI, LM Studio, Ollama и custom используют общий адаптер. Нативные Anthropic/Gemini в этой версии ещё не реализованы. Поддержка конкретного endpoint зависит от его совместимости с `/chat/completions` и SSE.

## Данные и ключи

По умолчанию данные лежат в **`.axiom/` в корне проекта**:

| Файл                                   | Содержимое                                                       |
| -------------------------------------- | ---------------------------------------------------------------- |
| `axiom.sqlite`                         | Диалоги, сообщения, вложения, конфигурации без ключей, настройки |
| `axiom.sqlite-wal`, `axiom.sqlite-shm` | Служебные файлы SQLite во время работы                           |
| `secrets.json`                         | Зашифрованные AES-256-GCM API-ключи                              |
| `master.key`                           | Локальный ключ шифрования                                        |

**Временное решение v0.1:** ключ шифрования находится рядом с зашифрованными секретами. Это исключает открытые API-ключи в SQLite и браузерном localStorage, но не защищает от пользователя/процесса с доступом к папке данных. На Windows `mode: 0600` не заменяет ACL. Храните папку в личном профиле с подходящими правами; дальнейший desktop-релиз должен использовать Windows Credential Manager/DPAPI или keychain через `SecretStorage`. История и вложения в SQLite не зашифрованы.

Ключи передаются при сохранении только локальному API, не возвращаются клиенту и не пишутся в логи. Пустое поле при изменении сохраняет старый ключ; отдельный флажок удаляет его. Копировать или переносить базу и секреты следует после остановки сервера. Не теряйте `master.key`.

Для другой папки данных (PowerShell):

```powershell
$env:AXIOM_DATA_DIR = "$env:LOCALAPPDATA\Axiom"
npm start
```

В production порт меняется переменной `PORT`. Dev-прокси настроен на 3001. Приложение рассчитано на одного локального пользователя, слушает только loopback. Авторизации и многопользовательского режима нет; не публикуйте этот API в сеть без отдельной архитектуры доступа. Внешние запросы выполняются только при обращении к настроенному провайдеру; шрифты поставляются локально.

## Проверки

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Unit/integration-тесты проверяют жизненный цикл Core, отмену, блокировку одновременной генерации, замену истории, восстановление SQLite, Secret Storage, реестр, HTTP-контракт провайдера, SSE и API. E2E запускает production на `3101` с отдельной папкой `.axiom/e2e`. Внешние платные API в тестах не вызываются.

## Ограничения v0.1

Нет агентов, tools execution, поиска, MCP, памяти, RAG, image/video generation, Axiom Code или CLI. Их capabilities описывают модели, но не включают ещё не существующие функции интерфейса. Контекст автоматически ограничивается приблизительным бюджетом с сохранением последних целых ходов; точного tokenizer нет, поэтому провайдер всё ещё может отклонить недооценённый контекст. Последний ход, который не помещается, отклоняется до изменения истории. Один активный ответ на диалог, без параллельных ветвей; UI блокирует смену диалога во время ответа. Ответы после редактируемого сообщения заменяются, а не архивируются в дерево версий. Проверка подключений показывает результат текущей попытки, не ведёт фоновый мониторинг. Поток не ограничен общей длительностью по умолчанию: действуют connection и idle timeouts; абсолютный предел опционален. PDF/Office и бинарные файлы не извлекаются.

## Hardening alpha.2

- ContextBuilder сохраняет непустые остановленные ответы в контексте; исключает ошибки и пустые остановленные сообщения. Старые ходы отбрасываются только из запроса, не из базы.
- Timeout architecture отделяет ожидание HTTP headers, паузу между данными и опциональную общую длительность.
- Настройки записывает один последовательный writer; промежуточные снимки объединяются, ошибка последней записи сохраняет возможность повторить её.
- SQLite schema 2: индексируемые role/status/timestamps/model/provider; recovery использует индекс status. Транзакционный migration runner обновляет прежнюю БД автоматически.
- Четыре workspace-пакета экспортируют JavaScript, `.d.ts` и maps из `dist`. Core не зависит от UI, базы или провайдерных реализаций; это проверяется линтером.

## Сборка пакетов и разработка

`npm run build:packages` выполняет `tsc -b`: shared первым, затем core/providers/storage. `npm run typecheck` и `npm test` сначала обеспечивают актуальную сборку пакетов. `npm run build` затем проверяет весь проект, собирает Chat и API. Дополнительные bundler/tokenizer/ORM не добавлены.

`npm run dev` сначала собирает пакеты и запускает три процесса: TypeScript watch, API watch и Vite. Изменения `packages/*/src` пересобираются в `dist`; API следит за этим выводом. У приложений нет aliases на чужой `src`. Отдельный CLI/Node-потребитель может импортировать `@axiom/core` обычным ESM import после сборки.

При первом запуске alpha.2 миграции применяются к существующей `.axiom/axiom.sqlite`. Перед обновлением остановите старый процесс и сохраните резервную копию базы. Старый сервер alpha.1 не должен работать одновременно с новым на той же БД. Downgrade схемы не реализован; откат приложения требует восстановления старой резервной копии.

Для выбора Secret Storage используется `AXIOM_SECRET_BACKEND`; единственный поставляемый backend — `encrypted-file`. Неизвестное имя завершает запуск с ошибкой, а не незаметно ослабляет защиту. Подробная модель угроз — в SECURITY.md.

Для отдельного smoke уже запущенного dev-сервера: `node tests/dev-smoke.mjs`. Скрипт создаёт временный диалог, проверяет streaming/Stop и удаляет его.
