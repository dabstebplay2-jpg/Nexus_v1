# Provider System — alpha.2

## Контракт

`AIProvider` определён в `packages/shared/src/index.ts`:

```typescript
interface AIProvider {
  readonly id: string;
  listModels(signal?: AbortSignal): Promise<Model[]>;
  chat(request: GenerationRequest): Promise<GenerationResult>;
  streamChat(request: GenerationRequest): AsyncIterable<ProviderEvent>;
}
```

`GenerationRequest` содержит модель, типизированные сообщения и обязательный AbortSignal. `ProviderEvent` — delta или finish. `GenerationResult` — текст, причина завершения и необязательная статистика токенов. Общий `StreamingProvider` реализует `chat` через поток. Ошибки, которые можно показать пользователю, оформляются `AxiomError`; неизвестные ошибки скрываются общим сообщением. Не включайте в исключения ключи, Authorization и необработанные тела ответов.

## Реализовано

| Вид                 | Реализация                                                                             |
| ------------------- | -------------------------------------------------------------------------------------- |
| `mock`              | Axiom Mock, детерминированный текст, локальный контекст, медленный отменяемый поток    |
| `openai-compatible` | `GET /models`, `POST /chat/completions`, Bearer key при наличии, text/image input, SSE |

OpenAI, LM Studio, Ollama и custom — конфигурации второго адаптера. Нативные протоколы Anthropic и Gemini в v0.1 не реализованы. Возможность добавить их обеспечивается фабриками реестра, а не фиктивными успешными ответами.

## Подключения

Каждое подключение имеет собственный UUID. Несколько серверов одного kind не конфликтуют. Base URL не содержит `/chat/completions`; адаптер добавляет endpoint. URL должен использовать HTTP/HTTPS и не содержать credentials, query или fragment. Redirect запрещён, чтобы не отправить ключ на другой адрес. Timeouts разделены на connection, idle и absolute; подробности ниже. Старого абсолютного лимита streaming в 120 секунд больше нет.

Discovery `/models` ожидает `{ "data": [{ "id": "model-id" }] }`. Если endpoint недоступен, можно сохранить ручные ID через настройки. Проверка не делает платный chat-вызов. Успешное обнаружение объединяется с ручными моделями, сохраняет известные метаданные; удалять устаревшие модели можно при редактировании списка. Unknown capabilities не угадываются. Для discovered text/streaming считаются контрактом выбранного chat-адаптера; endpoint, который выдаёт не-chat модели, потребует ручной корректировки списка.

На уровне схемы `Model.capabilities` расширяем. Публичный UI v0.1 настраивает imageInput для списка подключения; более тонкие индивидуальные capabilities/contextWindow можно сохранить через Provider API. Tools/reasoning/web/imageGeneration/videoGeneration описываются метаданными, но не исполняются в v0.1. Адаптер отклоняет неизвестные ему части сообщений, а не теряет их молча.

## Как добавить адаптер

1. Создать файл в `packages/providers/src/`, реализовать `AIProvider` или унаследовать `StreamingProvider`. Импортировать доменные типы из shared. Код SDK/HTTP поставщика должен остаться в этом пакете.
2. Преобразовать `MessagePart` в нативный формат API. Проверять неподдерживаемые части; прокидывать AbortSignal во все операции; нормализовать события и ошибки.
3. Получать ключ через `SecretStorage.get(configuration.id)`, никогда не из React или localStorage.
4. Экспортировать адаптер и зарегистрировать фабрику в composition root (`apps/server/src/app.ts`):

```typescript
registry.register(
  'new-provider',
  (configuration, secrets) => new NewProvider(configuration, secrets),
);
```

5. Добавить соответствующий kind и необходимые поля в серверную схему конфигурации/форму настроек. Сейчас mutation API намеренно создаёт только `openai-compatible`; регистрация фабрики сама по себе не меняет UI или валидацию.
6. Вернуть `Model[]` с ID подключения в provider, locality и только достоверными capabilities. Если провайдер не поддерживает discovery, вернуть явно заданные модели и реализовать отдельную проверку доступности при необходимости.
7. Добавить контрактные тесты: несколько чанков, Unicode на границе чанков, остановка fetch, ошибка авторизации, rate limit, раннее закрытие потока, пустой ответ и моделирование мультимодальных частей.

Реестр не допускает дублирования kind и выдаёт понятную ошибку для незарегистрированного адаптера. Новый потребитель Core получает тот же интерфейс независимо от поставщика.

## Локальная проверка

`npm test` запускает тест OpenAI-compatible против собственного временного HTTP endpoint; настоящие API-ключи не нужны. Для ручной проверки запустите LM Studio/Ollama, включите совместимый сервер, создайте подключение и выберите фактический ID загруженной модели. Проверка с реальными внешними аккаунтами не входит в автоматические тесты.

## Таймауты

| Операция            | Connection (до HTTP headers) | Idle (без непустых bytes) | Absolute                 |
| ------------------- | ---------------------------- | ------------------------- | ------------------------ |
| Генерация           | 30 000 мс                    | 180 000 мс                | По умолчанию отсутствует |
| Discovery `/models` | 12 000 мс                    | 12 000 мс                 | 30 000 мс                |

Connection включает установку соединения и ожидание response headers. После headers начинается idle. Любой непустой сетевой chunk, включая SSE heartbeat/comment и часть UTF-8/JSON, сбрасывает idle; ожидание следующего текстового delta не используется как критерий активности. Для reasoning-сервера, который долго не отдаёт даже headers/heartbeat, увеличьте соответствующий предел.

RequestTimeouts владеет AbortController и всеми таймерами одного запроса. Пользовательский signal объединяется с ним, причина пользовательской отмены сохраняется. ProviderTimeoutError расширяет AxiomError, имеет kind `connection`, `idle` или `absolute` и HTTP status 504. Core превращает её в понятную ошибку сообщения и сохраняет частичный текст. Таймеры очищаются при завершении, ошибке, отмене и закрытии iterator.

Настройка — необязательный объект `timeouts` в ProviderConfiguration и POST/PUT `/api/providers`. Например, вместе с остальными полями подключения:

```json
{
  "timeouts": {
    "connectionMs": 120000,
    "idleMs": 300000,
    "absoluteMs": 1800000
  }
}
```

Значения — положительные целые миллисекунды, не больше 2147483647. Отсутствующий `absoluteMs` отключает абсолютный предел streaming. Чтобы сбросить конфигурацию на defaults, передайте `timeouts: {}`. Обычное изменение формы подключений, не передающее timeouts, сохраняет существующие значения. Специальная новая UI-панель таймаутов в alpha.2 не добавлялась.

Контрактный тест проверяет активный поток HTTP дольше connection deadline и idle failure. Виртуальный clock детерминированно проверяет 600 секунд с heartbeat без absolute timeout — тест не ждёт десять реальных минут. Настоящие облачные reasoning-модели этим тестом не подменяются.

## Сборка

Публичные exports пакета — `dist/index.js` и `dist/index.d.ts`. После добавления адаптера используйте `npm run build:packages`; dev watcher делает это автоматически при изменении исходников. Providers зависит только от shared, а не от React/Core/SQLite. ContextBuilder передаёт уже отобранные сообщения; адаптер не должен самостоятельно незаметно удалять историю.
