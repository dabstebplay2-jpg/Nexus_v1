# Nexus — AI no-code chat

Nexus — React/Vite сайт с простым AI-чатом в стиле GPT. Пользователь пишет задачу обычными словами, а Nexus помогает разложить её по шагам: структура сайта, тексты, UX-логика, no-code план и следующий шаг.

Проект больше не строится как обычное портфолио или лендинг с фейковыми блоками. Основной интерфейс — это чат и скрытая левая панель с историей диалогов.

## Что уже работает

* React + Vite
* минимальный интерфейс в стиле GPT
* основной экран в виде AI-чата
* скрытая левая панель, которую можно открыть кнопкой
* создание нового чата
* история чатов в `localStorage`
* открытие старых чатов из истории
* удаление отдельных чатов
* очистка всей истории
* отправка запросов к AI через локальный backend-middleware Vite
* безопасная схема: API-ключ не попадает во frontend
* подключение к PolzaAI через OpenAI-compatible API
* загрузка доступных моделей через `/api/models`
* автоматический выбор модели из доступных моделей API-ключа
* отправка сообщений через `/api/chat`
* готовая serverless-функция `api/chat.js` для Vercel
* готовая serverless-функция `api/models.js` для Vercel

## Главная логика продукта

Nexus рассчитан на пользователя, который может вообще не понимать сайты, UX, дизайн, разработку и no-code.

Пользователь не должен выбирать сложные настройки. Он просто пишет, что хочет сделать, например:

```text
Хочу сайт для аренды квартиры с отдельным входом, кухней и ванной.
```

Nexus должен сам:

* понять задачу;
* предложить решение по умолчанию;
* разложить задачу по шагам;
* дать структуру сайта;
* предложить тексты;
* объяснить UX-логику;
* дать no-code план;
* предложить следующий конкретный шаг.

## Инструкции для нейросети

Внутри `AiStudio.jsx` используется системная логика для Nexus AI.

Основные правила поведения ассистента:

* отвечать простыми словами;
* не перегружать пользователя терминами;
* сначала давать готовое решение, а не заставлять пользователя самому думать;
* если данных не хватает, предложить разумный вариант по умолчанию;
* задавать не больше 3 уточняющих вопросов;
* всегда завершать ответ следующим конкретным шагом;
* если пользователь просит сайт — давать структуру, блоки, тексты, UX-логику и no-code план;
* если пользователь просит лендинг — думать про заявку, оффер, доверие и CTA;
* если пользователь просит портфолио — помогать упаковать опыт, навыки и кейсы;
* если пользователь просит UX-аудит — находить проблемы и предлагать исправления;
* если пользователь просит маркетплейсы — думать про карточку, SEO, визуал, рекламу и конверсию.

## Как подключить PolzaAI API-ключ

В корне проекта создай файл `.env`.

Можно через PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

Заполни `.env` так:

```env
OPENAI_API_KEY=твой_ключ_от_polzaai
OPENAI_BASE_URL=https://polza.ai/api/v1
OPENAI_MAX_OUTPUT_TOKENS=1600
```

`OPENAI_MODEL` больше не нужен, потому что сайт сам получает список доступных моделей через `/api/models`.

Названия переменных начинаются с `OPENAI_`, потому что PolzaAI используется как OpenAI-compatible API.

После изменения `.env` останови сервер и запусти заново:

```powershell
Ctrl + C
npm run dev -- --host 127.0.0.1
```

## Как работает backend

Frontend не обращается к PolzaAI напрямую.

Схема такая:

```text
React-компонент → /api/chat или /api/models → server/aiService.js → PolzaAI API
```

Это нужно для безопасности: API-ключ хранится только на серверной стороне и не попадает в браузер.

## API endpoints

### `/api/models`

Получает список моделей, доступных для текущего API-ключа.

Используется для автоматического выбора модели в интерфейсе.

### `/api/chat`

Отправляет сообщение пользователя в выбранную модель и возвращает ответ ассистента.

## Важно про безопасность

Никогда не вставляй API-ключ:

* в React-компоненты;
* в файлы внутри `src/`;
* в README;
* в публичный GitHub-репозиторий.

Ключ должен быть только:

* в `.env` локально;
* в Environment Variables на Vercel.

Файл `.env` должен быть добавлен в `.gitignore`.

## Если модели не загружаются

Проверь:

1. Есть ли файл `.env` в корне проекта.
2. Правильно ли указан `OPENAI_API_KEY`.
3. Правильно ли указан `OPENAI_BASE_URL`.
4. Перезапущен ли сервер после изменения `.env`.
5. Есть ли endpoint `/api/models`.
6. Есть ли обработчик `/api/models` в `vite.config.js` для локального запуска.

После правок перезапусти:

```powershell
Ctrl + C
npm run dev -- --host 127.0.0.1
```

## Деплой на Vercel

1. Загрузи проект в GitHub.
2. Импортируй репозиторий в Vercel.
3. В Vercel → Project Settings → Environment Variables добавь:

```text
OPENAI_API_KEY
OPENAI_BASE_URL
OPENAI_MAX_OUTPUT_TOKENS
```

4. Нажми Deploy.

После деплоя frontend будет обращаться к:

```text
/api/chat
/api/models
```

А Vercel будет выполнять serverless-функции:

```text
api/chat.js
api/models.js
```
