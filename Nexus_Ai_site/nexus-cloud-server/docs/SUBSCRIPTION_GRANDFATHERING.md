# Политика grandfathering подписок

**Версия:** 2026-06-03  
**Выбранный вариант:** **A** (мягкий переход)

## Правило

1. **Новые покупки** и продления после окончания текущего оплаченного периода — по **актуальным** ценам из `TIER_*_PRICE_USD` / каталога `/billing/catalog`.
2. **Уже оплаченный период** (`subscription_period_start` … `subscription_period_end`) — без изменения тарифа, пула и доступа: пользователь сохраняет условия до даты окончания периода.
3. Смена суммы следующего счёта происходит **только** при создании нового инвойса после истечения периода (или при добровольном апгрейде на более высокий тариф).

## Что не делаем

- Не пересчитываем задним числом `monthly_cap` для активного периода.
- Не храним отдельную колонку `legacy_price_usd` — цена фиксируется в записи `invoices.amount_rub` на момент оплаты.

## Коммуникация

При понижении цены PRO ($112→$100) и ULTRA ($224→$200) в UI можно указать: «новая цена при следующем продлении» — без принудительного досрочного изменения.

## Исключения

- Ручная выдача тарифа через `grant_tier` / admin — по усмотрению поддержки.
- `NEXUS_TESTING_MODE` — не распространяется на прод-пользователей.

## Деплой (Render / Vercel)

После merge в `nexus-cloud-server`:

1. Убедиться, что на Render **нет** переопределений `TIER_*_PRICE_USD` со старыми значениями (11 / 22 / 112 / 224). Если переменные заданы — обновить на **10 / 20 / 100 / 200** или удалить, чтобы использовались defaults из кода.
2. Проверить `GET /v1/billing/catalog`: `STANDARD.price_usd === 20`, `PRO` === 100, `ULTRA` === 200.
3. Фронтенд: redeploy Vercel — каталог подтянется с API; fallback в `usePricingCatalog` уже обновлён.
